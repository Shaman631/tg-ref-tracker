# Трекер подписчиков по реферальным ссылкам Telegram

Каждый вечер в 21:00 (Europe/Samara) для каждого канала создаётся **новая пригласительная
ссылка**, Telegram сам считает, сколько людей по ней пришло, а бот присылает вам отчёт.

```
📊 Реферальные ссылки — 2026-11-09

@my_channel
• Ссылка: https://t.me/+AbCdEf
• Пришло по ссылке сегодня: 12 (всего по ссылке: 12)
• Подписчиков в канале: 1543 (+18 за день)

Итого за день: +12 подписчиков по ссылкам
```

Проект работает на чистом Python 3.8+ без внешних зависимостей. Основной сценарий —
**запуск целиком на Android через Termux**: код, база и бот живут на телефоне, а управлять
ими можно прямо из Telegram, с того же телефона.

---

## Как это работает

1. Бот создаёт в каждом канале пригласительную ссылку на текущий день (`createChatInviteLink`).
2. Telegram ведёт счётчик `join_count` по каждой ссылке — сколько человек реально пришло.
3. Вечером скрипт снимает статистику, считает прирост за день и шлёт отчёт в Telegram.
4. Всё складывается в локальную базу `reflinks.db` (SQLite) — историю можно смотреть и выгружать.
5. Бот работает фоновым процессом и отвечает на команды `/daily`, `/stats`, `/links`,
   `/newlinks`, `/status`, `/restart` — управлять можно с телефона из Telegram.

Подписчики, пришедшие **не** по пригласительной ссылке (по прямой ссылке на канал, из поиска),
в счётчик ссылки не попадают — это ограничение Telegram, а не скрипта.

## Запуск на Android (Termux) — основной сценарий

Всё живёт на телефоне: Termux держит Python, cron и фонового бота. Вы управляете трекером
из Telegram — с того же телефона.

### Шаг 1. Установите Termux

Ставьте **с F-Droid** (https://f-droid.org/packages/com.termux/) — версия из Google Play
не обновляется и работает неправильно. Дополнительно поставьте **Termux:Boot** оттуда же
(нужен для автозапуска после перезагрузки телефона).

### Шаг 2. Положите проект на телефон

Способ А — через deploy key (нужны `git` и `openssh`, они ставятся в Termux):

```bash
pkg install git openssh
bash deploy/setup-git.sh ~/tg-ref-tracker
```

Скрипт создаст ключ, покажет его публичную часть и ссылку
https://github.com/Shaman631/tg-ref-tracker/settings/keys/new — вставьте ключ туда,
право «Allow write access» не нужно. Повторите ту же команду — проект склонируется.

Способ Б — архивом: скиньте `tg-ref-deploy.zip` на телефон любым способом и выполните:

```bash
cd ~
unzip -o tg-ref-deploy.zip
mv tg-ref-tracker/* tg-ref-tracker/ 2>/dev/null; mv tg-ref-tracker/.gitignore tg-ref-tracker/ 2>/dev/null; true
cd ~/tg-ref-tracker
```

### Шаг 3. Установите трекер

```bash
bash deploy/setup-termux.sh
```

Скрипт поставит `python`, `cron`, `openssh`, `termux-boot`, создаст `config.json` из
шаблона, пропишет crontab (ежечасная догоняющая проверка + watchdog бота каждые 10 минут),
запустит cron и бота, а также создаст скрипт автозапуска `~/.termux/boot/run-tg-ref.sh`.

### Шаг 4. Настройка (токен вводится со скрытием)

```bash
cd ~/tg-ref-tracker
python tg_ref.py wizard
```

Мастер задаст 5 вопросов:

1. **Токен бота** — вводится со скрытием (символы не отображаются, в историю команд не попадает).
2. Проверит токен и покажет username вашего бота.
3. **Каналы** — введите через запятую: `@my_channel, @second_channel`.
4. **Куда присылать отчёты** — мастер сам найдёт ваш `chat_id`: напишите боту `/start`
   в Telegram, и он подхватит сообщение. Если бот уже запущен, мастер на секунду
   остановит его, чтобы не забрать ваше сообщение, и поднимет обратно.
5. Итоговая проверка прав по каждому каналу.

Бот должен быть **администратором** каждого канала с правом «Приглашать пользователей»
(Управление каналом → Администраторы → Добавить).

### Как не засветить токен

- **Никогда не присылайте токен в чат** — ни в этот чат, ни в Telegram-группу, ни в
  issues. Переписка сохраняется, и токен утечёт. Вводите его только на самом устройстве.
- В мастере ввод скрыт: символы не echoes на экране и не попадают в `~/.bash_history`.
- Токен лежит в `config.json` с правами `600` (доступен только вашему пользователю Termux).
- `config.json` добавлен в `.gitignore` — в репозиторий токен не попадёт. Шаблон без
  токена лежит рядом в `config.example.json`.
- Если не хотите держать токен в файле — задайте переменную окружения
  `export TG_BOT_TOKEN=...` в `~/.bashrc`; она перекрывает значение из `config.json`.
- Сменить токен поздно можно безопасно: `python tg_ref.py config set token` — снова
  спросит скрыто, старый перезапишется.
- Утечка? Отзовите токен в @BotFather (`/revoke`) и впишите новый через мастер.

### Шаг 5. Проверьте и запустите первый раз

```bash
python tg_ref.py setup        # токен и права по каждому каналу
python tg_ref.py wizard       # если настройка нужна с нуля (токен вводится скрыто)
./deploy/daily.sh             # создать ссылки дня и прислать отчёт
```

### Шаг 6. Настройте Android, чтобы не убивало

- **Батарея**: Настройки → Приложения → Termux → Батарея → «Без ограничений» (иначе
  Android убьёт фоновые процессы).
- **Автозапуск**: на MIUI/HyperOS есть отдельный тумблер «Автозапуск» в настройках Termux.
- **Termux:Boot** — чтобы после перезагрузки телефона всё поднялось само.
- **Закрепите Termux** в списке недавних приложений, чтобы Android его не выгружал.
- Если Android всё равно убивает бота — watchdog поднимет его в течение 10 минут, а
  команды, отправленные в Telegram пока бот был выключен, Telegram хранит и выполнит сразу
  после запуска (до 24 часов).

### Управление с телефона

Пишите боту в Telegram — команды или кнопки под сообщением:

| Команда | Что делает |
|---|---|
| `/daily` | полный цикл: создать ссылки дня + собрать статистику + прислать отчёт |
| `/stats` | отчёт прямо сейчас |
| `/links` | ссылки дня по всем каналам |
| `/newlinks` | создать ссылки дня вручную |
| `/status` | состояние системы: аптайм, ближайший запуск, последний отчёт |
| `/restart` | перезапустить бота (поднимет watchdog) |
| `/channels` | список каналов и статус прав |

Кнопки «🌙 Полный цикл», «📊 Отчёт», «🔗 Ссылки дня», «🆕 Создать ссылки» делают то же
самое одним нажатием.

## Развёртывание на Render.com

Render — облачная платформа, где проект работает всегда. Нюанс тарифов (проверено по
документации Render): **бесплатно доступен только Web Service**; фоновые воркеры и cron
задачи требуют платного плана ($7/мес и $1/мес соответственно), а бесплатный web service
засыпает после 15 минут без входящих запросов.

Поэтому в проекте есть режим `serve`: **один процесс делает всё** — поднимает HTTP-сервис
(обязательный для Render), крутит бота и внутренний планировщик ежедневной задачи.

### Вариант А — бесплатно (один Web Service)

**1. Создайте сервис**

Render → **New → Blueprint** → подключите репозиторий `Shaman631/tg-ref-tracker` → укажите
ветку `main` и файл `render.yaml`. Либо **New → Web Service** → репозиторий → вручную:

- Build Command: `pip install --no-cache-dir -r requirements.txt`
- Start Command: `python tg_ref.py serve`
- Health Check Path: `/health`

Репозиторий приватный — при подключении дайте Render'у доступ через GitHub App
(в настройках интеграции отметьте этот репозиторий).

**2. Заполните переменные окружения** (Environment):

| Переменная | Значение |
|---|---|
| `TG_BOT_TOKEN` | токен от @BotFather |
| `TG_REPORT_CHAT_ID` | ваш chat_id (бот ответит на `/start`) |
| `TG_CHANNELS` | каналы через запятую: `@my_channel,@second_channel` |
| `TG_WEB_KEY` | ключ веб-страницы управления (сгенерируйте любой: `openssl rand -hex 16`) |
| `TG_BACKUP_CHAT_ID` | чат для бэкапа базы (обычно тот же, что `TG_REPORT_CHAT_ID`) |
| `TG_SCHEDULE_TIME` | `21:00` (по умолчанию) |
| `TG_TIMEZONE` | `Europe/Samara` (по умолчанию) |

Токен в Render попадает только в зашифрованные переменные окружения — в коде и в репозитории
его нет.

**3. Первый запуск.** Откройте `https://<имя-сервиса>.onrender.com/health` — должен ответить
JSON `{"ok": true, ...}`. На странице логов увидите запуск бота и планировщика.

**4. Управление с телефона.** Откройте `https://<имя-сервиса>.onrender.com/?key=<TG_WEB_KEY>`
и сохраните страницу в закладки телефона: на ней кнопки «Полный цикл», «Отчёт», «Ссылки
дня», «Состояние системы». Работает и из Telegram — команды бота те же.

**5. Чтобы сервис не засыпал** (бесплатный тариф засыпает через 15 минут тишины):

- зарегистрируйте бесплатный монитор [UptimeRobot](https://uptimerobot.com/) на проверку
  `https://<имя-сервиса>.onrender.com/health` с интервалом 5 минут — это не даёт сервису
  уснуть, и внутренний планировщик честно срабатывает в 21:00;
- либо поднимайтесь по ссылке с телефона — сервис просыпается за ~1 минуту.

**6. История переживает редеплой.** На бесплатном тарифе файлы на диске стираются при каждом
редеплое и рестарте. Поэтому после каждой ежедневной задачи состояние базы автоматически
сохраняется файлом в Telegram, а при старте сервиса — восстанавливается. Указатель на
последний бэкап хранится в описании профиля бота. Вручную: пришлите боку сохранённый файл
`tg_ref_state.json.gz` — он восстановит базу.

### Вариант Б — платно, без пингера (рекомендуется для постоянной работы)

- **Background Worker** (от $7/мес): `startCommand: python tg_ref.py worker` — бот и
  планировщик работают без сна, без пингера.
- **Cron Job** (от $1/мес): `python tg_ref.py daily` — если планировщик внутри воркера не
  нужен.
- **Persistent Disk** ($0.25/ГБ/мес): подключите диск, смонтируйте в `/var/data` и задайте
  `TG_REF_DB=/var/data/reflinks.db` — тогда история не стирается вовсе, а бэкап в Telegram
  остаётся как страховка.

В Blueprint это уже заложено: раскомментируйте блок `disk` и добавьте `TG_REF_DB`.

### Если хотите через Docker

В `render.yaml` замените `runtime: python` на `runtime: docker` — `Dockerfile` уже в проекте
(образ `python:3.12-slim`, healthcheck, порт из `$PORT`).

### Что где лежит

| Команда | Назначение |
|---|---|
| `python tg_ref.py serve` | режим Render: HTTP + бот + планировщик (точка входа web service) |
| `python tg_ref.py worker` | режим Render Worker: бот + планировщик, без HTTP |
| `python tg_ref.py daily` | одна задача (для Render Cron Job) |
| `python tg_ref.py backup` | сохранить базу файлом в Telegram |
| `python tg_ref.py restore` | восстановить базу из последнего бэкапа |

HTTP-эндпоинты: `GET /health` (проверка живости), `GET /?key=…` (страница управления),
`POST /api/run`, `POST /api/stats`, `GET /api/links`, `GET /api/status`.

## Локальный запуск на Windows (альтернатива)

Для пробного запуска на своём компьютере (PowerShell):

```powershell
cd E:\tg
python tg_ref.py wizard        # мастер настройки, токен вводится скрыто
python tg_ref.py setup          # проверка прав
python tg_ref.py daily --send   # создать ссылки и прислать отчёт
```

Фоновый бот на Windows — отдельной запускалкой:

```powershell
deploy\botctl.cmd start    # запустить (своё окно "tg-ref-bot")
deploy\botctl.cmd status   # проверить
deploy\botctl.cmd stop     # остановить
```

Ежедневный запуск в 21:00 настраивается задачей планировщика MiniMax Code
(она уже создана для папки `E:\tg`) — на сервере её заменяет cron из панели.

## Развёртывание на хостинге (shared hosting / панель)

> Альтернатива Termux. Локально на ПК ничего настраивать не нужно: папка проекта — это
> просто исходники, которые заливаются на хостинг.

### Шаг 1. Получите проект на сервере

Два способа — выберите любой.

#### Способ А: через deploy key (рекомендуется)

Проект лежит в приватном репозитории `Shaman631/tg-ref-tracker`. Скрипт создаст на сервере
SSH-ключ, покажет его публичную часть и подскажет, куда её вставить. Дальше обновления
делаются одной командой `git pull`.

```bash
cd /home/USER/tg          # если папки нет — положите туда только deploy/setup-git.sh
chmod +x deploy/setup-git.sh
./deploy/setup-git.sh /home/USER/tg
```

Скрипт:

1. создаст ключ `~/.ssh/tg_ref_deploy` (если его ещё нет);
2. добавит `github.com` в `known_hosts`;
3. проверит доступ к GitHub и, если ключ ещё не зарегистрирован, покажет его и ссылку —
   https://github.com/Shaman631/tg-ref-tracker/settings/keys/new
   (вставить публичный ключ, галочку *Allow write access* можно не ставить — нужен доступ на чтение);
4. после того как вы добавили ключ в GitHub, повторите `./deploy/setup-git.sh /home/USER/tg` —
   он склонирует проект, создаст `config.json` из шаблона и выставит права.

#### Способ Б: архивом

Если SSH-доступ к GitHub с сервера неудобен — залейте `tg-ref-deploy.zip` через файловый
менеджер панели и распакуйте:

```bash
cd /home/USER && unzip tg-ref-deploy.zip && cd tg-ref-tracker
cp config.example.json config.json
```

В обоих случаях дальше идёт одинаково:

```bash
cd /home/USER/tg
chmod +x deploy/*.sh
```

### Шаг 2. Создайте бота в Telegram

1. [@BotFather](https://t.me/BotFather) → `/newbot` → получите токен вида `7123456789:AAH...`.
2. В каждом канале: **Управление каналом → Администраторы → Добавить администратора** → ваш бот.
   Обязательное право — **«Приглашать пользователей»** (`can_invite_users`). Без него
   Telegram не даст боту создавать ссылки.

### Шаг 3. Заполните config.json

Скопируйте `config.example.json` в `config.json` (в репозитории `config.json` нет — он в
`.gitignore`, чтобы токен случайно не уехал в Git) и впишите:

- `bot_token` — токен из BotFather (или задайте переменную окружения `TG_BOT_TOKEN`);
- `report_chat_id` — ваш chat_id: напишите боту в Telegram `/start`, он ответит вашим id;
- `channels` — список каналов (`@username` или `-100xxxxxxxxxx`).

```bash
cd /home/USER/tg
python3 tg_ref.py wizard
```

Мастер спросит токен (ввод скрыт), каналы и сам найдёт ваш `chat_id` по команде `/start`.
Либо по отдельности:

```bash
python3 tg_ref.py config set token      # спросит скрыто
python3 tg_ref.py config set chat        # спросит chat_id
python3 tg_ref.py channels add @my_channel
```

Права на файл с токеном:

```bash
chmod 600 config.json
```

### Шаг 4. Проверьте, что всё настроено

```bash
cd /home/USER/tg
./deploy/check.sh
```

Скрипт покажет состояние окружения, версию Python, наличие токена, каналов и базы.
Если чего-то не хватает — выведет точный список.

### Шаг 5. Запустите бота в фоне

```bash
./deploy/botctl.sh start      # запустить
./deploy/botctl.sh status     # проверить
./deploy/botctl.sh logs       # журнал
./deploy/botctl.sh stop       # остановить
```

Теперь бот отвечает в Telegram:

| Команда | Что делает |
|---|---|
| `/links` | ссылки дня по всем каналам |
| `/newlinks` | создать ссылки дня прямо сейчас |
| `/stats` | собрать и прислать отчёт немедленно |
| `/channels` | список каналов и статус прав |
| `/start` | показать ваш chat_id и подсказку |

> Некоторые хостинги убивают фоновые процессы после выхода из SSH. Если бот не переживает
> переподключение, запустите его в tmux: `tmux new -d -s tgbot './deploy/botctl.sh start'`.

### Шаг 6. Настройте cron в панели

Откройте в панели раздел **Cron Jobs** (cPanel) или **Планировщик задач** (Plesk/Hestcp)
и добавьте три задачи из `deploy/cron.txt`.

Если панель поддерживает `CRON_TZ` (обычная cron):

```cron
CRON_TZ=Europe/Samara
0 21 * * *   /home/USER/tg/deploy/daily.sh
30 21 * * *  /home/USER/tg/deploy/daily.sh --catchup
*/10 * * * * /home/USER/tg/deploy/botctl.sh ensure
```

Если **не** поддерживает — время считается в часовом поясе сервера. Проверьте его командой
`date` и переведите 21:00 Самары (UTC+4): это 17:00 UTC, 20:00 МСК, 18:00 CET.

Что делает каждая задача:

- `daily.sh` — создаёт ссылки дня, снимает статистику, шлёт отчёт;
- `daily.sh --catchup` — страховка: если первый запуск не случился (хост спал, cron опоздал),
  догоняет; повторов не будет, скрипт помнит, что отчёт за день уже уходил;
- `botctl.sh ensure` — каждые 10 минут проверяет, что бот жив, и поднимает его, если упал.

### Шаг 7. Первая проверка

```bash
cd /home/USER/tg
./deploy/daily.sh          # создаст ссылки и пришлёт отчёт прямо сейчас
tail -n 40 logs/daily.log
```

Если отчёт пришёл в Telegram — система работает. Дальше всё пойдёт по расписанию.

## Команды (на сервере)

| Команда | Что делает |
|---|---|
| `python3 tg_ref.py daily` | создать ссылки + статистика + отчёт |
| `python3 tg_ref.py daily --if-due` | выполнить, только если задача наступила и ещё не выполнена |
| `python3 tg_ref.py links create` | создать ссылки дня вручную |
| `python3 tg_ref.py links list --days 14` | последние ссылки и их join_count |
| `python3 tg_ref.py stats` | снять статистику без отправки |
| `python3 tg_ref.py stats --send` | снять и отправить отчёт |
| `python3 tg_ref.py report --date 2026-11-08` | переслать сохранённый отчёт за дату |
| `python3 tg_ref.py channels list` | список каналов |
| `python3 tg_ref.py health` | диагностика окружения и настроек |
| `python3 tg_ref.py wizard` | пошаговая настройка, токен вводится со скрытием |
| `python3 tg_ref.py config set token` | ввести/сменить токен (скрытый ввод) |
| `python3 tg_ref.py bot` | бот-режим (обычно запускается через `botctl.sh`) |
| `python3 tg_ref.py config set schedule 21:00` | изменить время автосоздания |

### Как менять время

Время хранится в `config.json` (`schedule_time`), но фактический момент запуска задаёт cron
в панели. Меняем в двух местах:

```bash
python3 tg_ref.py config set schedule 20:00
```

и правило cron в панели (21:00 → 20:00 в нужном часовом поясе). После этого и скрипт,
и планировщик будут согласованы.

## Как считается прирост

- У каждой ссылки свой счётчик `join_count`, он растёт с момента создания ссылки.
- Ссылка дня создаётся в 21:00 → за день она набирает `join_count` подписчиков.
- Скрипт сохраняет снапшот счётчика и считает разницу, поэтому повторные запуски в тот же
  день не затирают накопленный прирост, а **прибавляют** его.
- Общее число подписчиков канала берётся отдельно (`getChatMemberCount`) — так видно и
  «трафик не по ссылкам».

## Обновление на сервере

Если проект ставился через deploy key:

```bash
cd /home/USER/tg
./deploy/update.sh
```

Скрипт выполнит `git pull`, перезапустит бота и проверит настройки. `config.json`,
`reflinks.db` и `logs/` в `.gitignore` — ваши настройки и статистика не затрагиваются.

Если проект заливался архивом — замените файлы вручную и перезапустите бота:

```bash
./deploy/botctl.sh stop
# заменить tg_ref.py новой версией
./deploy/check.sh
./deploy/botctl.sh start
```

База `reflinks.db` и `config.json` при обновлении не трогаются. Схема базы дополняется
автоматически при первом запуске.

## Ограничения

- Считаются только переходы **по пригласительной ссылке**. Прямые заходы на `@username`
  или из поиска в счётчик ссылки не попадают — их видно только как рост числа подписчиков
  в канале.
- Статистика по ссылке доступна, пока бот администратор канала и сама ссылка не отозвана.
- Один бот может обслуживать сколько угодно каналов — просто добавьте их в `channels`.
