# Трекер подписчиков по реферальным ссылкам Telegram

Каждый вечер в 21:00 (Europe/Samara) для каждого канала создаётся **новая пригласительная
ссылка**, Telegram сам считает, сколько людей по ней пришло, а бот присылает вам отчёт.

```
📊 Реферальные ссылки — 2026-11-09

@my_channel
• Ссылка: https://t.me/+AbCdEf
• Пришло по ссылке сегодня: 12 (всего по ссылке: 12)
• Подписчиков в канале: 1543 (+18 за день)

Итого за день: +12 подписчиков по ссылкам
```

Проект рассчитан на **shared hosting / панель без root**: работает на чистом Python 3.8+,
внешних зависимостей нет, всё запускается через cron из панели.

---

## Как это работает

1. Бот создаёт в каждом канале пригласительную ссылку на текущий день (`createChatInviteLink`).
2. Telegram ведёт счётчик `join_count` по каждой ссылке — сколько человек реально пришло.
3. Вечером скрипт снимает статистику, считает прирост за день и шлёт отчёт в Telegram.
4. Всё складывается в локальную базу `reflinks.db` (SQLite) — историю можно смотреть и выгружать.
5. Бот работает фоновым процессом и отвечает на команды `/links`, `/newlinks`, `/stats`, `/channels`.

Подписчики, пришедшие **не** по пригласительной ссылке (по прямой ссылке на канал, из поиска),
в счётчик ссылки не попадают — это ограничение Telegram, а не скрипта.

## Развёртывание на хостинге (shared hosting / панель)

> Локально ничего настраивать не нужно: папка проекта — это просто исходники, которые
> заливаются на хостинг. Локальное задание планировщика MiniMax Code на 21:00 приостановлено.

### Шаг 1. Залейте файлы на сервер

Через SSH, SFTP или файловый менеджер панели положите папку в домашний каталог, например
`/home/USER/tg`. Должно получиться:

```
/home/USER/tg/
├── tg_ref.py
├── config.json          ← заполнить (см. шаг 3)
├── config.example.json
├── reflinks.db          ← создастся сам
├── deploy/
│   ├── daily.sh
│   ├── botctl.sh
│   ├── check.sh
│   └── cron.txt
├── logs/                ← создастся сам
└── selftest/            ← можно не заливать
```

```bash
cd /home/USER/tg
chmod +x deploy/*.sh
```

### Шаг 2. Создайте бота в Telegram

1. [@BotFather](https://t.me/BotFather) → `/newbot` → получите токен вида `7123456789:AAH...`.
2. В каждом канале: **Управление каналом → Администраторы → Добавить администратора** → ваш бот.
   Обязательное право — **«Приглашать пользователей»** (`can_invite_users`). Без него
   Telegram не даст боту создавать ссылки.

### Шаг 3. Заполните config.json

Скопируйте `config.example.json` в `config.json` (в репозитории `config.json` нет — он в
`.gitignore`, чтобы токен случайно не уехал в Git) и впишите:

- `bot_token` — токен из BotFather (или задайте переменную окружения `TG_BOT_TOKEN`);
- `report_chat_id` — ваш chat_id: напишите боту в Telegram `/start`, он ответит вашим id;
- `channels` — список каналов (`@username` или `-100xxxxxxxxxx`).

```bash
cd /home/USER/tg
python3 tg_ref.py config set token 7123456789:AAH...
python3 tg_ref.py config set chat 123456789
python3 tg_ref.py channels add @my_channel
python3 tg_ref.py channels add -1001234567890
```

Права на файл с токеном:

```bash
chmod 600 config.json
```

### Шаг 4. Проверьте, что всё настроено

```bash
cd /home/USER/tg
./deploy/check.sh
```

Скрипт покажет состояние окружения, версию Python, наличие токена, каналов и базы.
Если чего-то не хватает — выведет точный список.

### Шаг 5. Запустите бота в фоне

```bash
./deploy/botctl.sh start      # запустить
./deploy/botctl.sh status     # проверить
./deploy/botctl.sh logs       # журнал
./deploy/botctl.sh stop       # остановить
```

Теперь бот отвечает в Telegram:

| Команда | Что делает |
|---|---|
| `/links` | ссылки дня по всем каналам |
| `/newlinks` | создать ссылки дня прямо сейчас |
| `/stats` | собрать и прислать отчёт немедленно |
| `/channels` | список каналов и статус прав |
| `/start` | показать ваш chat_id и подсказку |

> Некоторые хостинги убивают фоновые процессы после выхода из SSH. Если бот не переживает
> переподключение, запустите его в tmux: `tmux new -d -s tgbot './deploy/botctl.sh start'`.

### Шаг 6. Настройте cron в панели

Откройте в панели раздел **Cron Jobs** (cPanel) или **Планировщик задач** (Plesk/Hestcp)
и добавьте три задачи из `deploy/cron.txt`.

Если панель поддерживает `CRON_TZ` (обычная cron):

```cron
CRON_TZ=Europe/Samara
0 21 * * *   /home/USER/tg/deploy/daily.sh
30 21 * * *  /home/USER/tg/deploy/daily.sh --catchup
*/10 * * * * /home/USER/tg/deploy/botctl.sh ensure
```

Если **не** поддерживает — время считается в часовом поясе сервера. Проверьте его командой
`date` и переведите 21:00 Самары (UTC+4): это 17:00 UTC, 20:00 МСК, 18:00 CET.

Что делает каждая задача:

- `daily.sh` — создаёт ссылки дня, снимает статистику, шлёт отчёт;
- `daily.sh --catchup` — страховка: если первый запуск не случился (хост спал, cron опоздал),
  догоняет; повторов не будет, скрипт помнит, что отчёт за день уже уходил;
- `botctl.sh ensure` — каждые 10 минут проверяет, что бот жив, и поднимает его, если упал.

### Шаг 7. Первая проверка

```bash
cd /home/USER/tg
./deploy/daily.sh          # создаст ссылки и пришлёт отчёт прямо сейчас
tail -n 40 logs/daily.log
```

Если отчёт пришёл в Telegram — система работает. Дальше всё пойдёт по расписанию.

## Команды (на сервере)

| Команда | Что делает |
|---|---|
| `python3 tg_ref.py daily` | создать ссылки + статистика + отчёт |
| `python3 tg_ref.py daily --if-due` | выполнить, только если задача наступила и ещё не выполнена |
| `python3 tg_ref.py links create` | создать ссылки дня вручную |
| `python3 tg_ref.py links list --days 14` | последние ссылки и их join_count |
| `python3 tg_ref.py stats` | снять статистику без отправки |
| `python3 tg_ref.py stats --send` | снять и отправить отчёт |
| `python3 tg_ref.py report --date 2026-11-08` | переслать сохранённый отчёт за дату |
| `python3 tg_ref.py channels list` | список каналов |
| `python3 tg_ref.py health` | диагностика окружения и настроек |
| `python3 tg_ref.py bot` | бот-режим (обычно запускается через `botctl.sh`) |
| `python3 tg_ref.py config set schedule 21:00` | изменить время автосоздания |

### Как менять время

Время хранится в `config.json` (`schedule_time`), но фактический момент запуска задаёт cron
в панели. Меняем в двух местах:

```bash
python3 tg_ref.py config set schedule 20:00
```

и правило cron в панели (21:00 → 20:00 в нужном часовом поясе). После этого и скрипт,
и планировщик будут согласованы.

## Как считается прирост

- У каждой ссылки свой счётчик `join_count`, он растёт с момента создания ссылки.
- Ссылка дня создаётся в 21:00 → за день она набирает `join_count` подписчиков.
- Скрипт сохраняет снапшот счётчика и считает разницу, поэтому повторные запуски в тот же
  день не затирают накопленный прирост, а **прибавляют** его.
- Общее число подписчиков канала берётся отдельно (`getChatMemberCount`) — так видно и
  «трафик не по ссылкам».

## Файлы

| Файл | Назначение |
|---|---|
| `tg_ref.py` | вся логика (Python 3.8+, без внешних зависимостей) |
| `config.json` | токен, список каналов, время, чат для отчётов |
| `config.example.json` | шаблон config.json с подсказками |
| `reflinks.db` | SQLite: ссылки, снапшоты join_count, дневная статистика |
| `deploy/daily.sh` | запуск ежедневной задачи (из cron) |
| `deploy/botctl.sh` | управление фоновым ботом: start/stop/status/logs/ensure |
| `deploy/check.sh` | проверка окружения и настроек |
| `deploy/cron.txt` | готовые строки для cron в панели |
| `selftest/` | офлайн-проверка на моке Telegram API (без токена) |

Токен можно не хранить в файле — задайте переменную окружения `TG_BOT_TOKEN`,
она перекрывает значение из `config.json`.

## Обновление на сервере

```bash
cd /home/USER/tg
./deploy/botctl.sh stop
# заменить tg_ref.py новой версией
./deploy/check.sh
./deploy/botctl.sh start
```

База `reflinks.db` и `config.json` при обновлении не трогаются. Схема базы дополняется
автоматически при первом запуске.

## Проверка без Telegram (для теста)

В папке `selftest` лежит мок Telegram API — можно прогнать весь путь (создание ссылок →
статистика → отчёт → повторный запуск) без реального токена:

```bash
python3 selftest/run_selftest.py
```

Ожидаемый финал: `✅ ВСЕ ПРОВЕРКИ ПРОЙДЕНЫ`.

## Ограничения

- Считаются только переходы **по пригласительной ссылке**. Прямые заходы на `@username`
  или из поиска в счётчик ссылки не попадают — их видно только как рост числа подписчиков
  в канале.
- Статистика по ссылке доступна, пока бот администратор канала и сама ссылка не отозвана.
- Один бот может обслуживать сколько угодно каналов — просто добавьте их в `channels`.
