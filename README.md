# Трекер подписчиков по реферальным ссылкам Telegram

Каждый вечер в 21:00 (Europe/Samara) для каждого канала создаётся **новая пригласительная
ссылка**, Telegram сам считает, сколько людей по ней пришло, а бот присылает вам отчёт.

```
📊 Реферальные ссылки — 2026-11-09

@my_channel
• Ссылка: https://t.me/+AbCdEf
• Пришло по ссылке сегодня: 12 (всего по ссылке: 12)
• Подписчиков в канале: 1543

Итого за день: +12 подписчиков по ссылкам
```

**PHP-версия** — три файла, без крона, без зависимостей и без Composer:

| Файл | Что делает |
|---|---|
| `index.php` | веб-страница управления с телефона + запуск задачи по кнопке |
| `worker.php` | демон: слушает команды Telegram и сам следит за временем |
| `lib.php` | общие функции: Telegram API, состояние, подсчёт прироста |

---

## Как это работает без крона

Крон не нужен вообще:

1. `worker.php` крутится постоянно и **сам** смотрит на часы — как только наступило
   `SCHEDULE_TIME`, он создаёт ссылки дня, снимает статистику и шлёт отчёт.
2. Веб-обработчик тоже проверяет время при каждом запросе. Значит, даже «спящий» сервис
   отработает по расписанию, если его кто-то разбудил (например, бесплатный монитор).

Никаких таймеров, никаких платных cron-задач: один процесс делает всё.

## Развёртывание на Render.com

### 1. Создайте сервис

Render → **New → Blueprint** → репозиторий `Shaman631/tg-ref-tracker` → файл
`render.yaml` (он в корне) → Apply.

Репозиторий приватный — дайте Render доступ через GitHub App (в настройках интеграции
отметьте этот репозиторий).

Render не поддерживает PHP нативно, поэтому сервис собирается из `Dockerfile` в корне
(образ `php:8.3-cli`, расширения не нужны).

### 2. Заполните переменные окружения

В Dashboard вашего сервиса → **Environment**:

| Переменная | Значение |
|---|---|
| `BOT_TOKEN` | токен от [@BotFather](https://t.me/BotFather) |
| `CHAT_ID` | ваш chat_id — бот ответит на `/start` |
| `CHANNELS` | каналы через запятую: `@my_channel,@second_channel` |
| `WEB_KEY` | необязательно: если пусто, ключ выводится из токена и не меняется |
| `SCHEDULE_TIME` | `21:00` (по умолчанию) |
| `TZ` | `Europe/Samara` (по умолчанию) |

Токен попадает только в зашифрованные переменные окружения — в коде и в репозитории его нет.

### 3. Бот должен быть админом каналов

В каждом канале: Управление каналом → Администраторы → Добавить бота, право
**«Приглашать пользователей»** (`can_invite_users`). Без этого Telegram не даст ни создать
ссылку, ни отдать статистику `join_count`.

### 4. Проверьте

```
https://<имя-сервиса>.onrender.com/health
```

```json
{"ok":true,"tz":"Europe/Samara","schedule":"21:00","channels":2,
 "chat_id_set":true,"worker_seen":"2026-11-09T21:00:04+04:00","links":2,"last_day":"2026-11-09"}
```

- `channels` — сколько каналов настроено (должно совпадать с `CHANNELS`);
- `worker_seen` — когда воркер последний раз отвечал (значит, он жив);
- `last_day` — за какой день уже есть отчёт.

### 5. Управление с телефона

Откройте `https://<имя-сервиса>.onrender.com/?key=<ключ>` и сохраните в закладки.
На странице одна кнопка — «Создать ссылки и прислать отчёт», плюс блок «Ссылки дня».

Ключ доступа узнать можно тремя способами:

1. **Dashboard → Environment → `WEB_KEY`**;
2. **Логи сервиса** — при старте печатается строка с ключом;
3. **Команда `/webkey` в Telegram** — бот пришлёт ключ и готовую ссылку с адресом сервиса.

Если `WEB_KEY` не задан, ключ выводится из токена бота и **не меняется** при перезапусках —
закладка в телефоне остаётся рабочей.

### 6. Чтобы сервис не засыпал

Бесплатный web service на Render засыпает после 15 минут без входящих запросов. Заведите
бесплатный монитор [UptimeRobot](https://uptimerobot.com/) на адрес
`https://<имя-сервиса>.onrender.com/health` с интервалом 5 минут: он не даст сервису уснуть,
и вечерняя задача отработает вовремя. Плюс `/health` сам запускает задачу дня, если пора.

### 7. Сохранение состояния

Состояние лежит в файле `state.json` (путь — `STATE_FILE`). На бесплатном тарифе диск
стирается при редеплое, поэтому:

- **платно**: подключите Persistent Disk, смонтируйте в `/var/data` и оставьте
  `STATE_FILE=/var/data/state.json` — история переживёт всё;
- **бесплатно**: состояние можно восстановить вручную — сохраните `state.json` в надёжное
  место (например, в заметки) и верните файл обратно на сервер.

## Команды бота в Telegram

| Команда | Что делает |
|---|---|
| `/daily` | создать ссылки дня и прислать отчёт |
| `/links` | ссылки дня по каналам |
| `/status` | расписание, каналы, время последнего отчёта |
| `/start` | подсказка и ваш chat_id |

## Локальный запуск

Нужен PHP 8.1+ (расширения не нужны):

```bash
export BOT_TOKEN=123456:AA...
export CHAT_ID=123456789
export CHANNELS=@my_channel,@second_channel
export SCHEDULE_TIME=21:00
export TZ=Europe/Samara
export STATE_FILE=./state.json

php worker.php &                      # воркер: команды + расписание
php -S 127.0.0.1:8080 index.php       # веб-страница
```

Страница — `http://127.0.0.1:8080/?key=<ключ>`; ключ выводится в консоль при старте.

### Проверка без Telegram

В репозитории есть мок Telegram API и сквозная проверка PHP-версии:

```bash
python php-selftest.py
```

Ожидаемый финал: `✅ ВСЕ ПРОВЕРКИ ПРОЙДЕНЫ`.

## Как считается прирост

- У каждой ссылки свой счётчик `join_count`, он растёт с момента создания.
- Ссылка дня создаётся в 21:00 → за день она набирает `join_count` подписчиков.
- В состоянии хранится последнее увиденное значение счётчика, поэтому повторные запуски
  **прибавляют** прирост, а не затирают его.
- Общее число подписчиков канала берётся отдельно (`getChatMemberCount`) — так видно и
  трафик не по ссылкам.

Подписчики, пришедшие **не** по пригласительной ссылке (прямая ссылка на канал, поиск),
в счётчик ссылки не попадают — это ограничение Telegram, а не скрипта.

## Файлы

|---|---|
